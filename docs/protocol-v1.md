# ClipBordcast 协议规范 v1

> 本文档是双端（Android / Windows）实现的**唯一事实来源**。
> 任何实现与本文档冲突时，以本文档为准；修改协议必须先改本文档并递增版本。

- 协议版本：`1`（消息字段 `v`）
- 适用范围：纯 LAN，无服务器，无账号体系
- 数据类型：仅文字（UTF-8），单条上限 64KB

---

## 1. 设备身份

| 概念 | 说明 |
|------|------|
| `deviceId` | 随机 UUID v4，首次启动生成，持久化，永不改变 |
| `deviceName` | 用户可读的设备名（如 `Sothe-PC`、`小米14`），可修改 |
| 长期密钥对 | Ed25519，首次启动生成。私钥：Android 存 Keystore，Windows 存 DPAPI 保护文件 |
| 信任库 | 已配对设备的 `{deviceId, deviceName, ed25519Pubkey, pairedAt}` 列表，本地持久化 |

---

## 2. 发现层（mDNS）

- 服务类型：`_clipbordcast._tcp.local.`
- 各端启动即注册服务并持续浏览同类型服务
- TXT 记录：

| Key | 值 | 说明 |
|-----|-----|------|
| `id` | deviceId | 身份标识，重连后不变 |
| `name` | deviceName | 展示用 |
| `v` | 协议版本 | 不匹配的端互显「版本不兼容」 |
| `port` | TLS 监听端口 | 默认 `47610`，冲突时自动顺延 |

- 发现 ≠ 信任。发现的设备分为两类：
  - **已配对**：出现在信任库 → 自动建立 TLS 连接；
  - **未配对**：显示为「待配对」，**不允许任何数据通信**。

---

## 3. 配对流程（一次性，SAS + SPAKE2 + TOFU）

```
发起方 A                                  确认方 B
   │──── TCP 连接 B:port ────────────────▶│
   │──── PAIR_REQ {idA, nameA, v} ────────▶│
   │                                       │ B 生成 6 位数字码 SAS，弹窗展示
   │                                       │ （60s 过期，仅展示一次）
   │   用户把 B 屏幕上的 6 位码输入到 A      │
   │◀═══ SPAKE2 密钥交换（口令=6位SAS）═══▶│  抗中间人/抗离线爆破
   │──── PAIR_CONFIRM {idA, pubKeyA} ─────▶│  用协商出的会话密钥加密
   │◀─── PAIR_CONFIRM {idB, pubKeyB} ─────│
   │        双方各自落盘对方公钥，配对完成     │
```

规则：

1. SAS 为 `000000`–`999999` 均匀随机，60 秒过期，一次性；
2. 同一来源连续失败 3 次，锁定配对接口 5 分钟；
3. 配对成功后双方立即重建 TLS 连接进入通信态；
4. 取消配对 = 本地删除对方公钥条目 → 此后握手一律拒绝（永久断交，除非重新配对）。

---

## 4. 通信层（TLS 1.3 over TCP）

- 配对时双方各自用 Ed25519 长期私钥签发**自签证书**；
- 建立连接时双向校验：对端证书公钥 == 信任库中 pinned 公钥，否则断开；
- 未配对设备完成不了上述校验 → **握手层拒绝，应用层永远收不到它的数据**；
- 重连策略：指数退避（1s → 2s → 4s … 上限 30s），mDNS 重新发现后立即触发重连；
- 每个已配对设备之间维持一条长连接，心跳 25s（`PING`/`PONG`）。

---

## 5. 消息格式

TLS 之上为 **长度前缀帧**：`[4字节大端长度][JSON UTF-8 正文]`，单帧上限 128KB。

### 5.1 剪贴板广播（核心消息）

```json
{
  "v": 1,
  "msgId": "018f3c4a-…-uuid-v4",
  "from": "device-uuid",
  "ts": 1758030759123,
  "type": "CLIP_TEXT",
  "hash": "sha256hex(utf8(text))",
  "payload": { "text": "839201" }
}
```

### 5.2 心跳

```json
{ "v": 1, "msgId": "…", "from": "…", "ts": 0, "type": "PING" }
{ "v": 1, "msgId": "…", "from": "…", "ts": 0, "type": "PONG" }
```

### 5.3 字段规则

| 字段 | 规则 |
|------|------|
| `v` | 协议版本，不等于本端版本的消息丢弃 |
| `msgId` | 每条消息唯一 UUID v4，用于日志与调试 |
| `ts` | 发送方 Unix 毫秒时间戳 |
| `hash` | `sha256(utf8(text))` 全小写 hex，用于去重 |
| `payload.text` | UTF-8，超过 64KB 的部分**发送前截断**并记录日志 |

---

## 6. 去重与防回环（双端必须严格实现）

1. **发送去重**：本端剪贴板变化时，计算 `hash`；与最近一次**发送或接收**的 hash 相同则忽略（窗口 5 秒）；
2. **回环抑制**：收到 `CLIP_TEXT` 后写入本端剪贴板，同时把 `hash` 记入「抑制窗口」（5 秒）；窗口期内本端监听回调触发时，若内容 hash 命中抑制窗口 → **不再广播**；
3. **过期**：`ts` 与本端时钟差超过 60 秒的消息丢弃（容忍 ±5s 时钟漂移）；
4. 同一局域网存在多个独立配对组（我家设备 vs 同事设备）互不感知——串扰在 §4 握手层已被掐死。

---

## 7. 安全约束

- 配对公钥永不跨网络传输，仅经配对流程交换；
- 无任何公网监听端口；
- 日志中 `payload.text` 一律只记录 `hash` 前 8 位 + 长度，**不落明文**；
- 可选功能（v1.x）：验证码类内容（正则 `^\d{4,8}$`）接收 60 秒后自动清空剪贴板。
